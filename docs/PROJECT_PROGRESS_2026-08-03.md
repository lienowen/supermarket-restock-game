# Supermarket Restock Game — 项目进度与下一步

> 更新日期：2026-08-03  
> 基线分支：`main`  
> 编写时基线提交：`d08192a8ed7b4c092b54eedbbc100822a6822a2a`

## 1. 当前结论

项目目前处于 **可运行开发版本，尚未达到发版候选（Release Candidate）标准**。

核心代码、十关流程、构建和部署已经比较稳定；第一关的操作节奏也完成了一轮重要简化。但是，第一关仍有明显的视觉素材问题，尤其是推车与开箱可乐箱的组合关系尚未验收通过。因此不能把“代码测试通过”理解为“第一关已经完整完成”。

当前判断：

- **代码与系统基础：稳定**
- **第一关玩法流程：基本完成，可继续打磨**
- **第一关 UI：完成第一轮减负，仍需桌面端验收**
- **第一关素材视觉：未完成验收**
- **上线准备：尚未开始最终审核包整理**

## 2. 已完成内容

### 2.1 项目结构与运行流程

- 十关主流程已经接通，关卡经济、星级和进度能够连续继承。
- Restock、Checkout、Cleaning、Order Hunt 等模式使用统一项目架构和场景边界。
- 第一关到第十关的主要运行流程已经通过自动化回归。
- CrazyGames SDK 生命周期和关卡进度上报已经通过十关流程检查。

### 2.2 第一关玩法

第一关已从重复操作较重的方案调整为引导型节奏：

- 原方案：6 层货架，每层点击 3 次，共 18 次补货操作。
- 当前方案：6 层货架，每层点击 1 次，自动展示 3 瓶商品，共 6 次补货操作。
- 后续挑战型补货关仍保持每层 3 次操作，没有削弱正式挑战。
- 自动化检查已确认：第一关一次操作后，货架画面实际出现 3 瓶，不是只修改了计数。
- 结算仍按 18 件商品统计。

### 2.3 第一关 UI 与引导

- 左上步骤卡已改为根据 Phaser Canvas 的实际位置和缩放定位。
- 玩家完成第一步后，步骤卡会缩小，减少持续遮挡。
- 补货阶段移除了类似“失效按钮”的灰色 `TAP A SHELF` 大块。
- HUD 用词已统一为货架层数，避免 ROW、SHELF 等概念混用。
- 第一关不加入倒计时，继续保持低压力引导体验。

### 2.4 角色与道具代码

- 补货阶段已经支持独立的补货动作状态。
- 旧的“站立人物旁边悬浮一瓶可乐”方案已经被替换。
- 推车、箱子目前在代码中支持前后层遮挡结构。
- 道具、人物比例和位置已经做过多轮校准。

注意：代码支持分层不等于最终视觉已经合格。当前推车与箱子组合仍有明显美术问题，详见第 4 节。

当前 UI Regression Audit 仍显示失败，实际失败点为：

- `desktopLevelOne = false`
- `mobileLevelOne = true`
- `distinctLevelSeven = true`
- `startResumesGameplay = true`
- `touchTarget = true`

也就是说，失败集中在 **第一关桌面端关卡简报/引导界面**，不是核心玩法、构建或十关流程失败。因为该步骤失败，后面的专项 UI 审计在同一次流程中被跳过，需要修复后重新完整运行。

## 4. 尚未完成与已知问题

### 4.1 P0：推车＋开箱箱子素材不合格

当前截图中，箱子看起来像一张贴纸放在推车上，具体问题：

- 箱子与推车平台透视不一致。
- 箱子底部接触点不成立，存在悬浮或插入车板的感觉。
- 前后遮挡关系不自然。
- 缺少合适的接触阴影。
- 继续依靠坐标微调无法彻底解决。

当前结论：**这一组素材没有验收通过，需要重新制作组合状态。**

推荐产物：

- 保留空推车状态素材。
- 新增 `cart-cola-open-combo.png`。
- 新组合图内直接包含推车、开箱箱子、正确透视、接触阴影和前沿遮挡。
- 游戏在装箱/开箱状态直接切换组合图，不再将独立箱子硬叠在推车上。

正式制作需要原始透明 PNG 或 PSD：

- 空推车原图
- 开口可乐箱原图

不应使用游戏截图作为最终切图来源，截图只适合位置参考。

### 4.2 P0：第一关桌面端简报审计失败

需要对照自动审计截图检查：

- 桌面端简报是否被 Canvas 留白、缩放或安全区影响。
- 文案、按钮、任务卡是否完整可见。
- 桌面端和移动端是否使用了不一致的布局判断。
- 修复后需要重新跑完整 UI Regression Audit。

### 4.3 P0：第一关最终视觉验收尚未完成

仍需从进入关卡到完成补货逐阶段检查：

1. 初始任务简报
2. 拿箱子
3. 装车
4. 推车/开箱
5. 逐层补货
6. 完成反馈
7. 结算界面

重点检查人物、推车、箱子、货架、提示卡之间的比例、接触、遮挡和视觉焦点。

### 4.4 P1：第一眼质感与反馈仍需加强

已加入基础反馈，但还需要统一：

- 点击、补货和货架完成的动画节奏
- 声音反馈
- 光影和阴影语言
- UI 面板的材质与层级
- 进入关卡后的视觉焦点
- 第一关完成时的小高潮

目标不是继续堆功能，而是让玩家打开游戏后觉得“这是一个完成度较高的游戏”。

### 4.5 P1：首屏加载仍偏重

当前发布包符合现有预算，但首屏仍加载多张 1.6–2.2 MiB 的高清 PNG，冷启动约 14.90 MiB。发版前需要评估：

- WebP/AVIF 转换
- 按关卡或模式延迟加载
- 高清背景降采样
- 重复素材和大图裁切
- JavaScript 分包

### 4.6 P1：依赖安全检查

CI 安装日志中 `npm audit` 仍报告高严重级别问题。需要在发版前确认：

- 问题是否只存在于开发/审计依赖
- 是否影响生产包
- 能否安全升级依赖而不引入回归

## 5. 第一关“完成”的验收标准

只有同时满足以下条件，第一关才可标记为完成：

- 推车＋开箱箱子组合图通过人工视觉验收。
- 人物补货动作、箱子和推车没有悬浮、穿插或贴纸感。
- 桌面和移动端简报都完整、清晰、无裁切。
- 六层货架可用 6 次操作完成，并实际显示 18 瓶。
- UI 不遮挡关键操作区。
- 从进入关卡到结算无明显穿帮或卡住。
- 124 项测试通过。
- 生产构建和发布包校验通过。
- Vercel 部署成功。
- 完整 UI Regression Audit 全绿。

## 7. 发版策略

当前不建议立刻提交审核。正确顺序是：

1. 先让第一关在视觉和操作上达到可展示标准。
2. 再确保十关完整流程没有回归。
3. 最后处理审核和商业化入口。

商业化不应提前硬塞进第一关。第一版可以优先考虑不打断操作的广告位置、明确的奖励广告，以及后续再评估付费内容。具体盈利方案需要在核心体验稳定后单独设计。

## 8. 当前项目定位

项目的主要问题已经不再是“有没有代码”，而是：

- 第一眼是否足够吸引人
- 第一关是否真正有趣、顺畅
- 素材是否像一个统一世界
- UI 是否让人自然理解下一步
- 玩家是否愿意继续下一关

后续每一项工作都应优先回答：**它是否直接提升玩家前五分钟的体验，以及是否提高成功发版的概率。**
