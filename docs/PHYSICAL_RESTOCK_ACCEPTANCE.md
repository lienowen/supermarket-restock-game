# 补货从空货位到满货位的强制验收规则

## 问题说明

旧实现存在两层假补货：

1. 关卡开始时预先创建整层商品，再通过极低透明度隐藏；上架成功后把整层透明度改为 1；
2. 超市场景背景图中已经画死了满柜饮料，即使 Phaser 货位对象数量为 0，玩家看到的冷柜仍然是满的。

上述两种情况都会让补货看起来像移除遮挡、点亮图片或在原商品上叠图，不是真实地把商品放上空货架。

两种实现均已废弃，禁止恢复。

## 强制规则

- 每个冷柜货位容量为 3 件商品。
- 空货位必须拥有 0 个商品对象，不能预生成商品后设为透明。
- 背景图片、环境贴图和装饰层中不得在任务冷柜区域露出任何画死的商品。
- 补货场景必须使用完全不透明的冷柜墙覆盖背景中的整段饮料陈列，不能只遮挡中间目标货位。
- 整段遮挡墙必须覆盖任务冷柜左右区域；左右使用封闭服务面板，中间两门为实际补货门。
- 每次正确操作只增加 1 件商品。
- 货位必须真实经历 `0/3 → 1/3 → 2/3 → 3/3`。
- `1/3` 和 `2/3` 时不能增加已完成货位数，也不能切换下一货位。
- 第 3 件商品落架后，该货位才判定完成并激活下一货位。
- 商品必须从打开的箱子或补货车位置移动到目标货架，落在货架基线上并保留。
- 6 个货位共需完成 18 次真实上架。
- Level 1、Level 2、Level 6、Level 10 都必须执行相同的真实库存规则。

## 自动验收

自动验收同时读取：

1. `RestockRushController.rowItemCounts` 中的库存状态；
2. Phaser 货架容器中的实际商品对象数量；
3. `RestockSceneController.stockedRows` 中的完成货位数；
4. `beverage-cooler-empty-shell` 的可见性、透明度、深度和背景遮挡标记；
5. 页面上的 `restockCoolerBackground=occluded` 状态。

上述状态必须满足：

- `0/3`：商品对象 0，完成货位数不增加，任务冷柜肉眼为空；
- `1/3`：商品对象 1，完成货位数不增加；
- `2/3`：商品对象 2，完成货位数不增加；
- `3/3`：商品对象 3，完成货位数增加 1；
- 六层完成：商品总数 18，每层均为 3；
- 空柜遮挡层必须完全不透明，并位于背景图之上、动态商品之下；
- 左右边缘不得露出背景图中原有的饮料商品。

## 截图验收

Level 1 必须生成并人工检查以下截图：

- `restock-visual-0-of-3.png`
- `restock-visual-1-of-3.png`
- `restock-visual-2-of-3.png`
- `restock-visual-3-of-3.png`
- `restock-contact-sheet.jpg`

人工检查不能只看计数，必须逐项确认：

- `0/3` 的任务冷柜和左右遮挡区域没有任何原背景商品；
- `1/3、2/3、3/3` 只增加本次动态放入的商品；
- 商品没有覆盖在其他饮料前面；
- 第 3 件完成后，目标框才移动到下一货位；
- 冷柜墙与场景连接自然，不出现只贴在满柜前面的窄黑框。

Level 2 专项验收还必须确认：

- 记忆预览结束前货位不可操作；
- 正式阶段不显示下一货位答案；
- 错误点击不改变正确目标；
- 同一个正确目标在 `1/3`、`2/3` 时保持不变；
- 第 3 件才进入下一目标；
- 最终完成 18 件商品。
